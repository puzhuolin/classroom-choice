# 课堂 · 情景模拟平台

一个入口，装所有情景。**以后只加情景，不改代码、不用重新部署。**

零第三方依赖，`node server.js` 即可运行。教师控制台 + 学生端 + 单人闯关 + 情景编辑器。

## 页面与权限

| 地址 | 是什么 | 谁用 | 要口令 |
|---|---|---|---|
| `/entry` | **入口页**：配一次服务器地址，老师四个入口 + 学生二维码都在这 | 老师（也可发到班级群） | ❌ |
| `/admin` | **口令页**：输入后台口令 | 老师 | — |
| `/` | **情景大厅**：所有情景的卡片墙 + 二维码 | 老师 | ✅ |
| `/play?s=id` | **单人闯关**：一个人走完一个情景，出结局与复盘 | 学生（预习/复习）| ✅ |
| `/teacher?s=id` | **课堂实时**：4 组同屏，实时看票数与各组判定 | 老师投屏 | ✅ |
| `/editor` | **情景编辑器**：表单增删改情景，保存即生效 | 老师备课 | ✅ |
| `/s` | **学生端**：只有当前情景，选不了、也看不到情景库 | 学生扫码 | ❌ |

- 后台口令默认 **`1949`**，用环境变量 `ADMIN_PIN` 改；设成 `off` 则关闭口令。
- 学生扫码只到 `/s`，看不到大厅、进不了编辑器，也拿不到正确解（投票结束后才下发）。
- 口令记在 cookie（30 天），也可用 `?pin=1949` 直达。

## 固定入口页（发给学生/同事的那个链接）

`/entry` 是一个自包含的入口页：填一次服务器地址（存在浏览器本地），四个教师入口 + 学生二维码就全部指向这台服务器。

- 公开版本放在 `https://workbuddy.link/p/deotKYlvxm592t9NTTivBh`，以后换服务器只需在页面上改地址，**这个链接永远不变**。
- 也可用 `?s=https://你的域名` 预先指定地址，发给不同班级用不同入口。

## 怎么增加一个新情景（不需要重新部署）

1. 打开 `/editor`（大厅右上角「＋ 新建情景」）。
2. **可选：⓪ 导入课件** —— 直接把 `.docx` / `.pptx` / `.txt` / `.md` 拖进来，页面在**浏览器里**解包抽文字（大 PPT 也不占服务器），自动切成若干幕并给每幕填 3 个待改的选项；也可以粘贴文字后点「按段落生成幕骨架」或「按幻灯片页生成」。
3. 填标题、图标，选结算方式：
   - **判断抉择**：每一幕有 1 个正确解，可再定义“几组关系”（如过程民主⇄成果民主），每组只要有一幕选偏就判为“没立住”。
   - **属性养成**：定义若干维度（如教育/科技/人才），每个选项加减维度值，看最终“综合国力”。
4. 每一幕：写「情景描述」+「问题」+ 2~5 个选项。判断型给正确解打勾、给错误选项标“偏向了哪一侧”；可再给每个选项写「结果」(text)、「理论对应」(anchor)、「讲评」(tip)。**每一幕还可以贴一张图或一段视频的网址**（`.jpg/.png` 或 `.mp4/.webm`，教师端与学生端都会显示）。
5. **封面图**在 ② 开场与角色 里填：大厅卡片、开场页、学生端等待页都会显示，配一句话图注。讲老旧小区这类题材，一张现场照片比十行文字管用。
6. 写结局（按顺序匹配，第一条符合的生效）、可选的教学板块（支持 HTML）、**⑦ 教学要点**（一行一条）、**⑧ 课堂讨论题**（一行一条）。
7. 点「💾 保存并生效」——**立刻**出现在大厅、`/play`、`/teacher` 的下拉里。学生刷新页面即可看到。

> 情景存在 `data/scenarios.json`。编辑器的「导出这个情景」可单独备份，大厅的「导出备份」可整库备份。

## 课堂实时怎么用

1. 大厅里对某个情景点「课堂用」→ 自动把该情景设为当前课堂情景（学生端标题随之改变）。
2. 点「开始上课」→ 学生扫码（`/s`）→ 输入名字 → 自动随机分成 4 组。
3. 每幕：点「开放投票」→ 学生作答 → 点「结束本轮投票」，选项会立刻标出 **✅ 正确解** 并弹出讲评条，可以直接对着大屏讲。
   - 同一时刻，**学生手机上会出现「你这一票的结果」**：对/错、后果、涉及哪一组关系偏向了哪一侧、对应的理论依据。
4. 右下方「各组对比分析」：判断型显示每组答对几题、哪组关系没立住、主要偏向哪一侧；属性型显示各维度增长与“增长主要来自哪一项”。
5. 「结束课堂」→ 出小组排名；**学生端立刻切到「个人复盘」**：得分与等级、结局、逐幕对错清单、需要补的几幕（附对应的教学内容锚点）、关系判定、本课教学要点、讨论题。

## 部署

Railway / Render / Replit 均可，根目录含 `server.js`、`store.js`、`seed.js`、`parse-doc.js`、`package.json`、`public/`（含 `img/`）、`data/`。

- `railway.json` 已配好 NIXPACKS + `node server.js`。
- 部署时在 Variables 里加 `ADMIN_PIN`（不设就是 `1949`）。
- **注意**：Railway 的文件系统是临时的，**重新部署会回到部署包里的 `data/scenarios.json`**。所以：
  - 部署前先把最新情景「导出备份」，部署后用大厅的「导入恢复」导回去；
  - 或者把导出的 `data/scenarios.json` 一起放进部署包再上传，一次到位。
- 数据在内存里，服务重启会清空学生与作答记录（不影响情景库，情景在磁盘上）。
- 旧数据自愈：如果 `data/scenarios.json` 里缺「教学要点 / 讨论题 / 教学板块」，启动时会按同 id 的种子自动补齐，自己改过的内容不会被覆盖。

## 已知限制

- 课堂实时模式用 1 秒轮询，单机（一个进程）即可支撑一个班的常规使用；多实例部署需要外部存储，当前未做。
- 情景里的「教学板块」允许写 HTML，属于信任环境（只有老师能进编辑器），不要开放给不信任的人。
- 媒体只支持直链（图片/视频网址），不支持上传图片文件；本地文件放 `public/img/` 后用 `/img/xxx.jpg` 引用（内置的电梯封面就是这么放的）。建议内网/图床/校内已有资源地址。
- 课件解析优先在浏览器里做（`DecompressionStream('deflate-raw')`），不支持的旧浏览器会回退到 `POST /api/parse`（上限 24MB）；老格式 `.doc` / `.ppt` 不支持，需另存为 docx/pptx。
