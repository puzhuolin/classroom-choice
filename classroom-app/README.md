# 课堂 · 情景模拟平台

一个入口，装所有情景。**以后只加情景，不改代码、不用重新部署。**

零第三方依赖，`node server.js` 即可运行。教师控制台 + 学生端 + 单人闯关 + 情景编辑器。

## 页面与权限

| 地址 | 是什么 | 谁用 | 要口令 |
|---|---|---|---|
| `/entry` | **入口页**：配一次服务器地址，老师四个入口 + 学生二维码都在这 | 老师（也可发到班级群） | ❌ |
| `/admin` | **口令页**：输入后台口令 | 老师 | — |
| `/` | **情景大厅**：所有情景的卡片墙 + 二维码 | 老师 | ✅ |
| `/play?s=id` | **单人闯关（备课自测）**：一个人走完一个情景，出结局与复盘 | 老师 | ✅ |
| `/solo?s=id` | **单人闯关（学生版）**：不分组、有单人榜；课堂进行中的情景自动锁住 | 学生 | ❌ |
| `/teacher?s=id` | **课堂实时**：4 组同屏，实时看票数与各组判定 + 现场操作台 | 老师投屏 | ✅ |
| `/editor` | **情景编辑器**：表单增删改情景，保存即生效 | 老师备课 | ✅ |
| `/s` | **学生端**：只有当前情景，选不了、也看不到情景库 | 学生扫码 | ❌ |

- 后台口令默认 **`1949`**，用环境变量 `ADMIN_PIN` 改；设成 `off` 则关闭口令。
- 学生扫码只到 `/s`，看不到大厅、进不了编辑器，也拿不到正确解（投票结束后才下发）。
- 口令记在 cookie（30 天），也可用 `?pin=1949` 直达。

## 怎么增加一个新情景（不需要重新部署）

1. 打开 `/editor`（大厅右上角「＋ 新建情景」）。
2. **可选：⓪ 导入课件** —— 直接把 `.docx` / `.pptx` / `.txt` / `.md` 拖进来，页面在**浏览器里**解包抽文字（大 PPT 也不占服务器），自动切成若干幕并给每幕填 3 个待改的选项；也可以粘贴文字后点「按段落生成幕骨架」或「按幻灯片页生成」。
3. 填标题、图标，选结算方式：
   - **判断抉择**：每一幕有 1 个正确解，可再定义“几组关系”（如过程民主⇄成果民主），每组只要有一幕选偏就判为“没立住”。
   - **属性养成**：定义若干维度（如教育/科技/人才），每个选项加减维度值，看最终“综合国力”。
4. 每一幕：写「情景描述」+「问题」+ 2~5 个选项。判断型给正确解打勾、给错误选项标“偏向了哪一侧”；可再给每个选项写「结果」(text)、「理论对应」(anchor)、「讲评」(tip)。**每一幕还可以贴一张图或一段视频的网址**（`.jpg/.png` 或 `.mp4/.webm`，教师端与学生端都会显示）。
5. **封面图**在 ② 开场与角色 里填：大厅卡片、开场页、学生端等待页都会显示，配一句话图注。讲老旧小区这类题材，一张现场照片比十行文字管用。
6. 写结局（按顺序匹配，第一条符合的生效）、可选的教学板块（支持 HTML）、**⑦ 教学要点**（一行一条）、**⑧ 课堂讨论题**（一行一条）。
7. 点「💾 保存并生效」——**立刻**出现在大厅、`/play`、`/teacher` 的下拉里。学生刷新页面即可看到。

> 情景存在 `data/scenarios.json`。编辑器的「导出这个情景」可单独备份，大厅的「导出备份」可整库备份。

## 「共和国抉择」的数值是怎么定的（改题前请先读）

这个情景的数据写在 `strategy-v2.js`（`seed.js` 里 `require` 它），设计目标是**不能靠算分找到标准答案**，否则一个班四个组会趋同。

- 每幕 4 条路线，净收益**全部等于 +24**：三条主线是 `+26 / +8 / −10`（各主推教育、科技、人才中的一维），第四条是另一种思路（双线并进 `+16/+16/−8`、孤注一掷 `+30/−3/−3`、三张单子各砍一点 `+8/+8/+8`）。
- 同一幕里没有任何一条“全面优于”另一条（脚本可校验：逐项比较 delta，不允许一维不差、另一维更高）。
- 结局只看**最弱一维**，不看总分：`minDim≥52 科教兴国` → `≥42 稳步前行` → 再按最弱维分 `无源之水 / 受制于人 / 有器无人`。“平均用力”不是最优解，“补短板”才是。
- 四条第四路线在六幕里是**混合类型、位置打乱**的。这一点很关键：如果每幕的“平衡选项”都固定在同一个位置，学生只要狂点那一格就能拿最好结局。
- 改完数值请重新穷举 `4^6 = 4096` 条路径，确认三件事：① 四个“幕幕都点同一位置”的机械策略都拿不到好结局；② 三档偏科的分布大致均衡（现在约 25% / 22% / 21%，稳步 21%，兴国 10%）；③ 三个维度的中位数接近（现在 60 / 64 / 64）。
- 选项文字只写“做什么”，结果文字只陈述代价，**不做道德评判**——学生要自己判断值不值。

## 两种模式、两张榜

| 模式 | 入口 | 排名 |
|---|---|---|
| 组队（课堂） | 学生扫 `/s` 码，自动随机分 4 组；老师 `/teacher` 投屏 | 课堂结束时按「综合国力」或「得分」出小组排名 |
| 单人闯关 | `/solo`（可带 `?s=情景id`），不需要口令 | 走完在结局页填名字提交，出**单人榜前 10** 和自己的名次 |

单人榜的规则，都是为了让它能用在一节真实的课上：

- **成绩由服务器重算**：提交的是“每一幕选了第几个”，分数在服务端按情景数据算，改前端改不出高分。
- **同名只留最好的一次**：同一个学生反复刷不会把榜占满。
- **上课中自动锁题**：`/solo/list` 会把“课堂正在用的那个情景”标成 locked，`/api/solo/scenario` 直接返回 403——避免有学生提前看到正确解。下课（`done`）之后自动解锁，学生可以回去补练。
- **榜单在内存里**，服务重启即清空，不占磁盘。

## 学生端看得到什么（不只是四个按钮）

`/s` 的每一幕按「背景 → 选择 → 后果」组织：

1. **进度条**：第几幕 / 共几幕，走过的幕变实心。
2. **情景背景**：每一幕的 `scene` 原文（衬线排版、左侧竖线），配这一幕的图片/视频——先知道“为什么现在要做这个决定”。
3. **上一手衔接**：一句话回顾“上一环节你们选了什么，结果是什么”，点开下方可看完整回顾。
4. **我这一路的三本账**：按 *你自己* 的选择累计的三维条（判题型显示本组得分）。
5. **开票后的后果**：属性型显示「这一手：教育 +26 / 科技 −10」+ 结果文字 + 理论对应；判题型显示对错、关系判定。**属性型不再出现“✘ 你选错了”**——它没有标准答案。
6. **组里多数**：本轮本组几票选了哪一项、和你是否一致，让“集体决策”这件事被学生看见。
7. **老师提示**：老师在操作台发的一句话，会出现在学生页顶部。
8. 结束后自动切「个人复盘」：结局、三维、逐幕选择与增减、教学要点、讨论题。

## 教师端操作台（不改代码就能救场）

投屏页右上角「🧰 现场操作台」，展开后：

- **老师提示**：一句话下发到所有学生手机（例：“想一想第 3 组的人才账”），可清空。
- **现场加减分**：选组 + 选维度（属性型）或总分（判题型），±5 / ±1，**只影响本局，不改情景数据**；「清零该组」恢复按选择算出的成绩。适合奖励讲得好的组，或把跑偏的分临时压回来。
- **单组重投**：某一组投错了/要重议，清掉该组本轮作答，其他组不受影响。
- **单人榜**：看本情景前 3、一键清空、打开 `/solo` 入口。
- **入口**：直达编辑器与情景大厅。

其余都在网页里做，不需要改代码：

| 想改什么 | 在哪改 |
|---|---|
| 情景文字、选项、维度数值、结局、教学要点 | `/editor`（支持导入 Word/PPT 生成草稿） |
| 换一节课用哪个情景 | 控制台左上角下拉，或大厅卡片「课堂用」 |
| 封面图 / 每幕插图 | 编辑器里填图片、视频网址 |
| 备份 / 迁移情景 | 大厅「导出备份 / 导入恢复」 |

## 课堂实时怎么用

1. 大厅里对某个情景点「课堂用」→ 自动把该情景设为当前课堂情景（学生端标题随之改变）。
2. 点「开始上课」→ 学生扫码（`/s`）→ 输入名字 → 自动随机分成 4 组。
3. 每幕：点「开放投票」→ 学生作答 → 点「结束本轮投票」，选项会立刻标出 **✅ 正确解** 并弹出讲评条，可以直接对着大屏讲。
   - 同一时刻，**学生手机上会出现「你这一票的结果」**：对/错、后果、涉及哪一组关系偏向了哪一侧、对应的理论依据。
4. 右下方「各组对比分析」：判断型显示每组答对几题、哪组关系没立住、主要偏向哪一侧；属性型显示各维度增长与“增长主要来自哪一项”。
5. 「结束课堂」→ 出小组排名；**学生端立刻切到「个人复盘」**：得分与等级、结局、逐幕对错清单、需要补的几幕（附对应的教学内容锚点）、关系判定、本课教学要点、讨论题。

## 部署

Railway / Render / Replit 均可，根目录含 `server.js`、`store.js`、`seed.js`、`strategy-v2.js`、`parse-doc.js`、`package.json`、`public/`（含 `img/`）、`data/`。

- `railway.json` 已配好 NIXPACKS + `node server.js`。
- 部署时在 Variables 里加 `ADMIN_PIN`（不设就是 `1949`）。
- **注意**：Railway 的文件系统是临时的，**重新部署会回到部署包里的 `data/scenarios.json`**。所以：
  - 部署前先把最新情景「导出备份」，部署后用大厅的「导入恢复」导回去；
  - 或者把导出的 `data/scenarios.json` 一起放进部署包再上传，一次到位。
- 数据在内存里，服务重启会清空学生与作答记录（不影响情景库，情景在磁盘上）。
- 旧数据自愈：如果 `data/scenarios.json` 里缺「教学要点 / 讨论题 / 教学板块」，启动时会按同 id 的种子自动补齐，自己改过的内容不会被覆盖。

## 已知限制

- 课堂实时模式用 1 秒轮询，单机（一个进程）即可支撑一个班的常规使用；多实例部署需要外部存储，当前未做。
- 情景里的「教学板块」允许写 HTML，属于信任环境（只有老师能进编辑器），不要开放给不信任的人。
- 媒体只支持直链（图片/视频网址），不支持上传图片文件；本地文件放 `public/img/` 后用 `/img/xxx.jpg` 引用（内置的电梯封面就是这么放的）。建议内网/图床/校内已有资源地址。
- 课件解析优先在浏览器里做（`DecompressionStream('deflate-raw')`），不支持的旧浏览器会回退到 `POST /api/parse`（上限 24MB）；老格式 `.doc` / `.ppt` 不支持，需另存为 docx/pptx。
